## 3. u151–u159 到底改了什么（物证结论）

1. **版本串证据（结论已作废，见 §3.5 更正）**：`strings vendor_boot_27-u1NN.img`
   的第一行版本标签在 u150 是 `(u150)`、u151 是 `(u151)`，u152–u159 仍是 `(u151)`。
   ~~即源码版本号从 u152 起没有再更新。~~ —— 该推断错误：版本号是**逐条 printf 硬编码**的，
   不是单一宏，同一个镜像里同时存在 `(u151)` 与 `(u155)` 两种标签，不能用来判断源码版本。
2. **启动参数证据**（payload 内嵌 boot 配置 TOML，105 个 token）：
   u150–u157 参数集**逐 token 完全一致**；u158、u159 与之相比**恰好只少
   `muyu_usb=1 muyu_usb_panic=1`**，其余 103 项不变。最后两轮把 USB 调试驱动
   从启动路径整体摘掉了。
3. **镜像字节证据**：u157→u158 全镜像只差 **989 字节**，聚类为 4 段：
   FAT 目录时间戳（`0xbfc0e`、`0xc04bc`）、`chosen random-seed`（256 B）、
   以及**启动参数区**（`0x5d3a15d..0x5d3a465`，即删除 muyu_usb 两项）。
   这是"只改参数"的形态。其余相邻轮之间差 4–18 MB，散布全镜像——与 LTO
   布局重排一致，不能据此断言有代码改动。

### 3.5 更正（2026-11-08 17:40，改 §1 与 §3.1/§3.3 的结论）

- 设备仓 `/tmp/spike27/package/` 与 `UniXNU-muyu/package/` 里那份 `MuyuUsbDebug.c`
  是 **11-01 的旧文件**（778 行，无 u1xx 标签），它并不是今天在跑的东西；

  **`tree/.cache/xnu-work/bsd/dev/arm/muyu_usb_debug.c`**（1336 行，mtime
  **2026-11-08 15:59**），它和 `osfmk/console/video_console.c` 的 575 行改动、
  `pexpert/arm/pe_init.c` 的 109 行改动一起，构成全部读屏能力；
- 这三处都在 `.cache` 里、都在那棵 **126 个未提交改动**的 git 树上（base 提交
  `ac9718f xnu-12377.121.6`），**一旦清缓存或换机器，读屏能力归零**。

所以正确结论是：**源码今天一直在改（15:59 还在改），而且从来没进过版本控制。**

## 4. Linux 侧观测通道（init_boot reader，已建成未上机）

`UniXNU-muyu/package/linux-log/`（`init`、`rb.c`、`build-initboot-reader.py`），
今天 15:19–15:26 定稿到 v3/v4。设计（源码头注释原文要点）：

- ABL 真正交给内核的 ramdisk 来自 **init_boot** 分区（boot.img 的 ramdisk_size=0 且
  bootloader 忽略 boot 镜像自带 ramdisk）；init_boot 的 vendor ramdisk（347 个模块）会
  **拼接在自定义 ramdisk 之后**，所以 `/lib/modules` 是满的、`/init` 是我们的。
- 原厂内核的约束（今天在板上实测）：`CONFIG_DEVTMPFS` 未开（/dev 要 mknod）、
  `CONFIG_VT` 未开（**面板从 Linux 侧无法显示**）、`CONFIG_DEVMEM` 未开（无法戳
  splash framebuffer）、**`CONFIG_PSTORE_CONSOLE` 开启 ⇒ printk 落在 ramoops
  `0xa7000000`，可被 XNU payload 读取上屏——这是唯一可用的输出通道**。
- 失败退出路径：`rb.c` 是无 libc 的 aarch64 `reboot(RESTART2, reason)` 小工具，
  用 reboot reason（`bootloader`/`recovery`）离开卡死的 Linux 启动——**热重启保留
  ramoops 内容，断电销毁**，所以绝不能碰电源键。
- v3 修复：上一版在 insmod 里挂死（pmic_glink/ucsi 等待 Android 用户态才拉起的
  传输），改为**先武装 60 s 独立进程看门狗**，shell 真正起来才解除，超时带 reason
  重启回 bootloader。
- v4 的头修正：不再自造 boot header（14:59 失败教训），**逐字采用原厂
  `fw/stock/init_boot.img` 的头**，只改 ramdisk 字节与 offset 12 的 size 字段
  （该头布局已对照 stock boot.img 与 stock init_boot.img 双重验证）。

**状态：host-verified（构建产物 + 头布局验证），未 device-verified（未刷、未跑）。**
